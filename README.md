# Mars Sample Return Mission

**Mars Sample Return Mission** — учебный проект для автоматизации процесса формирования и обработки миссий по сбору образцов марсианского грунта.

Система позволяет пользователям просматривать доступные образцы, добавлять их в миссию, формировать заявку на отправку миссии, а модераторам — управлять образцами и принимать или отклонять сформированные миссии.

## Назначение проекта

Проект моделирует работу информационной системы для планирования миссий на Марс.  
Пользователь выбирает интересующие образцы грунта, формирует миссию и отправляет её на рассмотрение. После этого модератор проверяет заявку и принимает решение: завершить миссию или отклонить её.

## Основные возможности

### Для пользователя

- регистрация и авторизация;
- просмотр списка образцов марсианского грунта;
- поиск образцов по названию;
- просмотр подробной информации об образце;
- создание черновика миссии;
- добавление образцов в миссию;
- удаление образцов из миссии;
- изменение данных миссии;
- отправка миссии на рассмотрение;
- просмотр своих миссий;
- фильтрация миссий по статусу и дате формирования;
- удаление черновика миссии.

### Для модератора

- создание новых образцов;
- редактирование информации об образцах;
- загрузка и обновление изображений образцов;
- удаление образцов;
- просмотр всех сформированных миссий;
- принятие миссии;
- отклонение миссии;
- фиксация результата выполнения миссии.

## Роли пользователей

В системе предусмотрены две основные роли:

| Роль | Возможности |
|---|---|
| Пользователь | Формирует миссии из доступных образцов и отправляет их на рассмотрение |
| Модератор | Управляет образцами и обрабатывает заявки на миссии |

Права доступа реализованы на уровне API. Обычный пользователь может работать только со своими миссиями, а модератор имеет доступ к управлению образцами и обработке заявок.

## Статусы миссий

| Код | Статус | Описание |
|---|---|---|
| 1 | Введён | Черновик миссии |
| 2 | В работе | Миссия отправлена пользователем на рассмотрение |
| 3 | Завершен | Миссия принята и завершена модератором |
| 4 | Отклонен | Миссия отклонена модератором |
| 5 | Удален | Черновик миссии удалён пользователем |

## Статусы образцов

| Код | Статус | Описание |
|---|---|---|
| 1 | Действует | Образец доступен для выбора |
| 2 | Удалена | Образец скрыт из общего списка |

## Основные модели данных

### Sample

Модель образца марсианского грунта.

Основные поля:

- `name` — название образца;
- `description` — описание;
- `status` — статус образца;
- `image` — изображение;
- `date_discovery` — дата обнаружения.

### Mission

Модель миссии.

Основные поля:

- `status` — текущий статус миссии;
- `date_created` — дата создания;
- `date_formation` — дата отправки на рассмотрение;
- `date_complete` — дата завершения;
- `owner` — пользователь, создавший миссию;
- `moderator` — модератор, обработавший миссию;
- `name` — название миссии;
- `success` — результат выполнения миссии.

### SampleMission

Связующая модель между миссией и образцами.

Основные поля:

- `sample` — выбранный образец;
- `mission` — миссия;
- `order` — порядок образца внутри миссии.

| Метод | URL | Описание |
|---|---|---|
| GET | `/api/samples/` | Получить список образцов |

## Авторизация

Авторизация реализована через `session_id`.

После успешного входа или регистрации сервер:

1. создаёт уникальный идентификатор сессии;
2. сохраняет связь `session_id → user_id` в Redis;
3. передаёт `session_id` клиенту через cookie.

Для доступа к защищённым методам пользователь должен быть авторизован.

## Начальное заполнение базы

При запуске через Docker Compose выполняются:

```bash
python manage.py makemigrations
python manage.py migrate --noinput
python manage.py flush --no-input
python manage.py fill_db
```

Команда `fill_db` создаёт:

- тестовых пользователей;
- тестовых модераторов;
- набор образцов марсианского грунта;
- изображения образцов в MinIO;
- тестовые миссии с разными статусами.

## Пример сценария работы

1. Пользователь регистрируется или входит в систему.
2. Пользователь просматривает список доступных образцов.
3. Пользователь добавляет несколько образцов в черновик миссии.
4. Система создаёт миссию со статусом `Введён`.
5. Пользователь отправляет миссию на рассмотрение.
6. Статус миссии меняется на `В работе`.
7. Модератор просматривает список миссий.
8. Модератор принимает или отклоняет миссию.
9. При принятии миссия получает статус `Завершен`.
10. При отклонении миссия получает статус `Отклонен`.

## Особенности реализации

- Для хранения данных используется PostgreSQL.
- Для хранения изображений используется MinIO.
- Для хранения пользовательских сессий используется Redis.
- API реализовано на Django REST Framework.
- Документация API доступна через Swagger.
- Для модераторов реализованы отдельные права доступа.
- Пользователь видит только свои миссии.
- Модератор может просматривать и обрабатывать все миссии.
- Удаление образцов и миссий реализовано через изменение статуса, а не физическое удаление из базы.
